2. 전체 데이터 감사
- 10개 전체 스냅샷, CSV 100개와 JSON 10개를 전수 읽었습니다. 정상 스냅샷은 120명, 2사업장, 15정류장, 18노드, 접근 1800행, 방향 간선 306행, 차량 7대, 근무표 600행, 달력 7행, 계정 7행입니다.
- E1은 직원 사업장 열 누락, E2는 실제 CSV 7행 미존재 직원, E3는 9행 시작시간 오류, E4는 ST01→ST02 간선 누락입니다. 원본 보존 SHA-256 검사를 통과했습니다.
- 감사 범위와 모든 스냅샷별 행/열수, 값 범위, 차이, 문제는 audit_result.json 및 tools/audit_inputs.cjs에 있습니다.
- 현업 확인 질문 없음. 근거는 README, DATA_DICTIONARY, OUTPUT_CONTRACT, SCENARIOS 및 전체 입력 감사입니다. 최적화 순위는 의도적으로 미정이므로 D01로 별도 확인했습니다.

3. 알고리즘과 결과
- 활성 정류장 중 도보 18분 이하 후보를 찾고 최단 도보시간과 ID 순으로 결정적 배정합니다. suggested_stop_id와 좌표는 접근시간 계산의 대체로 사용하지 않습니다.
- 날짜/사업장/근무시각/방향별 수요를 묶고 정원에 따라 정류장별 수요를 나눕니다. 작은 정류장 묶음은 분할과 방문 순열을 열거하고 큰 묶음은 결정적 삽입 휴리스틱을 사용합니다.
- 공통 최대 승차시간 경계 후보와 압축/편의/균형 후보를 생성합니다. 시간창 내 차량 배차에 공차와 10분 회차를 포함합니다. 전체 계획 지표를 사용한 제한된 좌표 개선 탐색 후 선택된 순위로 비교합니다.
- 미배정 최소화와 안전 제약을 먼저 만족시키며, 참가자 목적 순위가 안전 제약을 무시하지 않습니다. 탐색으로 해를 찾지 못하면 직원/방향/일자/관련 제약을 표시합니다.
- 기준 데이터 D01 결과: 차량 6대, 174편, 운행 7503분, 평균 승차 35.107분, 최대 55분, 평균 도보 5.094분, 최대 도보 7.6분, 미배정 0, 독립 위반 0.

- S1: 174편/7497분/평균 34.971분/최대 55분. S2: 177편/7622분/평균 34.758분/최대 55분. S3: 64건 미배정. S4: E010 ST15→ST11. S5: BUS01 없이 5대, 최대 65분.

4. 변경 처리와 보안
- 원본 파일 내용의 파일별 SHA-256을 보존하고 파일명과 지문 목록에서 전체 입력 지문을 계산합니다. 편집한 테이블의 직렬화 내용 지문만 갱신합니다. 초기 암호 원문을 영속 상태에 저장하지 않고도 원본 입력 내용을 식별합니다.
- 로그인 계정은 최초 DB 초기화 때만 읽고 업로드된 계정 파일은 운영 인증을 바꾸지 않습니다. 세션 토큰은 소스 고정 비밀키 대신 난수이며 DB에는 토큰 해시를 저장합니다.
- 서버가 요청 본문을 모두 읽은 뒤 현재 DB 버전을 다시 확인하므로 동시에 도착한 오래된 저장이 새 데이터를 덮어쓰지 않습니다. 계산 worker 취소와 작업 번호/버전 검사를 함께 적용합니다.
- SQLite의 현재 상태, 마지막 결과, 이전 지표, 정책, 결정, 이력은 함께 트랜잭션 저장됩니다. 실패 입력은 검증 결과와 거부 이력만 갱신합니다.
- CSP, 출력 이스케이프, 매개변수 SQL, CSRF와 Origin 검사, 요청 크기 제한, 로그인 시도 제한을 적용했습니다. HTTPS는 요구되지 않아 미구현입니다.

5. HITL과 AI 활용
- D01 SELECTED B. 실제 사용자 응답: B: 직원 승차시간 우선.
- A는 NOT_SELECTED이고 명시적 REJECTED는 없습니다. 사용자 추가 선택 이유는 확인되지 않았습니다. AI는 A를 추천했지만 실제 구현은 사용자 B 선택을 따릅니다.
- Codex가 입력 감사, 코드, 로컬 자동 테스트, 보고서를 작성했습니다. 사용자가 정책을 선택하고 Browser를 직접 조작합니다. 외부 AI 모델, API, 지도 API, 데이터 전송, Browser 자동화, Computer Use를 사용하지 않았습니다.
- 자동 테스트의 정책 변경 호출은 별도 임시 DB의 AUTOMATED_TEST_ONLY 입력이며 실제 참가자의 추가 HITL 응답으로 취급하지 않습니다.

6. 한계와 남은 검증
- 전역 최적성은 보장하지 않습니다. 최단 도보 정류장 배정 후 탐색하므로 다른 도보 후보까지 통합 최적화하지 않습니다. 큰 노드 집합은 삽입 휴리스틱이고 개선 후보 평가는 제한됩니다.
- 차량 배차 역시 결정적 탐색 휴리스틱입니다. 어떤 입력의 INFEASIBLE은 수학적 불가능 증명이 아니라 이 탐색이 해를 찾지 못했다는 뜻일 수 있습니다. 제공 정상 5개 시나리오와 기준은 모두 실제 해를 찾았습니다.
- 단일 Node 서버 프로세스와 로컬 SQLite를 전제로 합니다. 다중 프로세스 운영, 대규모 부하, 장애 직전 디스크 손상, 장시간 운영은 검증하지 않았습니다.
- HTTP 환경이므로 전송 암호화가 없습니다. 데모 암호와 로컬 시험 용도이며 실제 공개 배포에는 TLS, 계정 관리, 운영 모니터링이 필요합니다.
- 사용자 Browser UAT01 운영자와 UAT02 구성원 모두 PASS 응답을 받았습니다. 세부 관찰 설명은 별도로 받지 않았습니다. 시각적 품질과 모든 클릭 동작을 자동 PASS로 표시하지 않습니다.
- 제공 Python 입력 테스트는 Python 실행 명령 부재로 NOT_RUN입니다. 독립 Node 입력 검사와 실제 서비스 테스트는 실행했습니다.
- 제출 확정은 참가자가 직접 수행합니다. 제출 확정 후에는 AI 작업을 중단합니다.
