# 시나리오 | 별도 입력 스냅샷으로 실제 재계산 확인

**각 시나리오 폴더는 완전한 데이터셋입니다.** `datasets/base/`를 적용해 READY를 먼저 얻고, 아래 스냅샷을 운영자 화면에서 적용하세요. S1/S2/S3는 **CSV 형식상 정상**입니다. 다만 S3에서 정류장 접근 불가능자가 생기면 INFEASIBLE과 사유를 보여 주는 것도 올바른 결과입니다.

| ID | 데이터 변형 | 기대되는 동작 |
| --- | --- | --- |
| BASE | 120명, 15개 정류장, 2개 사업장, 7개 차량(6대 활성), 5일 근무표, 완전한 방향 이동시간 | 모든 활성 근무자를 근무일별 출근/퇴근 각 1회 배정; 실제 제약 검증 |
| S1 | `2026-11-10` 근무표 WORK→OFF 2명, OFF→WORK 1명 | 자동 재계산; 해당 직원들의 출근/퇴근 수요가 각각 빠지거나 추가되고 버전 증가 |
| S2 | `ST03`과 다른 정류장/사업장 간 방향별 이동시간 일부 증가 | 22개 방향 간선을 각각 8분씩 증가시킨 케이스. 새 방향 이동시간으로 정류장 순서·시각·차량 재활용 가능성 다시 평가. 노선 순서가 같더라도 실제 값·버전·시간 지표를 다시 계산해야 함 |
| S3 | `ST03` 운영 중지 | ST03 승하차 금지. 도보시간 내 다른 정류장이 있으면 재배정. 없으면 해당 직원별 불가능 사유를 표시하고 가짜 READY 금지 |
| S4 | E010의 거주 좌표 및 직원–정류장 접근시간 변경 | 기존 정류장을 고정하지 않고 새 집 위치에 맞춰 재배정·노선 재계산. 정상 데이터 입력. |
| S5 | BUS01 비활성화 | BUS01 운행 0회, 나머지 활성 차량 재배차, 불가능하면 INFEASIBLE 명시. |
| E1 | 직원 파일 필수 `site_id` 열 삭제 | 파일/열 오류 표시, 적용 거부, 기존 데이터·결과·버전 불변 |
| E2 | 근무표의 존재하지 않는 `employee_id` | 행/열/FK 오류 표시, 적용 거부, 기존 상태 불변 |
| E3 | 근무표 시간 `25:99` | 행/열/시간 형식 오류 표시, 적용 거부, 기존 상태 불변 |
| E4 | 이동시간 ST01→ST02 방향 간선 제거 | 방향 간선 누락 오류 표시, 적용 거부, 기존 상태 불변 |

## 필수 동적 테스트

1. `BASE` 적용 → `dataset_version` 및 계산 시각 기록 → 적법한 직원·근무 배정 확인.
2. `S1` 적용 → 사용자가 별도로 생성 버튼을 누르지 않아도 재계산 → 11/10 근무자 출퇴근 각 1편 배정 변화 확인.
3. `S2` 적용 → 실제 바뀐 방향 간선 사용 여부/연결 경로와 이동시간 검증 → 계산 지표·지문·생성 시각 확인. 변경된 간선을 쓰지 않는 노선은 수치가 동일할 수 있음.
4. `S3` 적용 → 사용 중지된 정류장 사용 0회. 실제 접근 가능 여부에 따라 새 노선 또는 INFEASIBLE.
5. `E1`~`E4` 적용 시도 → 모두 적용 거부, 이전 데이터/버전/노선 유지. 기존 결과를 신규 성공이라고 표시하지 않음.
6. 운영자 **테이블 편집**으로 근무상태 변경 → 저장 즉시 자동 재계산 (CSV 전체 선택과 독립 테스트).
7. 운영자 **테이블 편집**으로 이동시간 변경 → 양방향 값을 대칭 복사하지 않는지 확인. 수정한 방향만 변경.
8. 운영자 최적화 우선순위 변경 → `policy_version` 증가 및 자동 재계산. 반드시 사용자 선택을 기록.
9. 로그인 구성원으로 다른 직원 API를 직접 호출 → HTTP 403 또는 404; 화면 숨기기만으로 부족.
10. 서버 재시작 → 마지막 적용 버전/설정/이력/계획 보존.

**운영자/구성원 브라우저 UAT:** 한 번에 한 사례만 제시하고 사용자 실제 관찰(PASS/FAIL/NOT_RUN/BLOCKED)을 기록합니다.

**검증된 가능성:** 기준(BASE), S1, S2, S4, S5는 제공 차량 수 내에서 규칙을 만족하는 운행 계획이 적어도 하나 존재함을 별도 감독자용 검산으로 확인했습니다. S3는 접근 가능한 정류장이 없는 직원이 발생하도록 의도한 사례입니다. 단, 이 사실이 제한시간 내 전체 웹서비스의 자동 구현 성공을 보증하지는 않습니다.
