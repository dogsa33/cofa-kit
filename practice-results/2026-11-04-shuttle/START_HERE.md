# 연습 진행자용 시작 안내

이 폴더에는 **모의 과제만** 있습니다. `cofa-kit`/기존 `cofa-ready-kit`/정답 앱을 포함하지 않습니다.

1. 새 빈 연습 폴더에 이 패키지 파일을 복사합니다.
2. Codex를 **과제 폴더 루트**에서 실행하여 먼저 `README.md`를 읽게 합니다.
3. 실제 Cofa Probe에서 키트를 가져오던 방식을 재현하려면 별도 `.cofa-kit` 폴더에 공개 `https://github.com/dogsa33/cofa-kit.git`을 Clone한 다음, Codex에게 `.cofa-kit/prompts/SCENARIO.md`를 읽도록 지시합니다.
4. **진행자는 최적화 우선순위를 일부러 미정으로 유지**합니다. Codex가 사용자에게 물을 때 대안을 확인하고 실제로 선택합니다. 무응답이나 '알아서'를 승인으로 기록하면 실패입니다.
5. 실제 브라우저에서 로그인·정류장 배정·시간표·변경 후 자동 재계산·권한 분리까지 시험합니다.
6. 연습 후 별도 **감독자 팩**의 체크리스트와 검증기를 사용합니다. 감독자 팩은 Codex의 과제 폴더에 넣지 않습니다.

사용자에게 전달할 가장 짧은 시작 요청:

```text
이 폴더의 README.md를 실제 과제 지시로 먼저 읽어. .cofa-kit/prompts/SCENARIO.md와
필요한 SKILL.md를 읽고 요구를 추출해. 최적화 목표처럼 사용자에게 중요한 선택은
대안·근거를 먼저 설명하고 한 번에 하나씩 물어봐. 내 선택을 실제로 받은 뒤 구현해.
코드는 직접 실행·테스트하고, 데이터 변경 후 자동 재계산과 권한 검사를 반드시 확인해.
웹 Browser UAT는 내가 직접 진행할 테니 한 건씩 안내해.
```

데이터셋 형식 사전 점검(풀이 프로그램 아님):

```bash
python tools/check_datasets.py datasets/base
python -m unittest discover -s tests -v
```

이 두 명령 통과는 **제공 문제 데이터의 형식 정상**을 의미할 뿐, 지원자의 웹앱 완성이나 노선 알고리즘 성공이 아닙니다.

## 연습용 데이터 검증 현황 (v1.1)

- BASE/S1/S2/S4/S5는 **실제로 6대 이내에 실행 가능한 노선이 존재함**을 별도의 감독자 검증으로 확인했습니다. 노선 정답 파일은 본 패키지에 포함하지 않습니다.
- S3는 의도적으로 정류장 접근이 불가능한 근무자가 발생합니다. `INFEASIBLE` 및 영향받은 구성원 사유를 정확하게 제시하면 올바른 동작입니다.
- 출근 도착은 시작 20~40분 전, 퇴근 출발은 종료 10~30분 후여야 합니다.
- 데이터셋 자체의 검증과 **웹앱/자동 재계산/보안 구현 성공은 완전히 별개**입니다.
