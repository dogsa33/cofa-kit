1. 실행 환경과 명령
- Node.js 24 이상이 필요합니다. 현재 환경 Node.js v24.22.1에서 실행했습니다.
- 외부 패키지 설치가 필요 없습니다. npm install, 외부 API, 지도 SDK를 사용하지 않습니다.
- 과제 루트에서 node server.cjs 또는 npm start를 실행합니다.
- 기본 바인딩은 0.0.0.0:3000이고 접속 주소는 http://localhost:3000 입니다.
- 포트 변경: PowerShell에서 $env:PORT='3001' 을 설정한 뒤 node server.cjs 를 실행합니다. 서버가 출력한 실제 포트를 사용합니다.
- 종료는 해당 서버 터미널에서 Ctrl+C입니다. 사용자 UAT 중에는 서버를 유지합니다.
- 테스트: node --test tests/service.test.cjs 또는 npm test 입니다.
- 입력 전체 감사: node tools/audit_inputs.cjs 입니다. 원본은 수정하지 않습니다.
- 기준 결과 다시 생성: node tools/export_base.cjs 입니다. artifacts/route_plan.json을 현재 명시적 D01 정책으로 계산합니다.

2. 합성 테스트 계정
- 운영자: admin_demo / AdminDemo!2026
- 구성원: worker001 / Worker001!2026
- 다른 합성 계정은 원본 datasets/base/demo_accounts.csv를 확인합니다.
- 이 암호는 문제에서 제공한 합성 데모 전용입니다. 사용자 DB에는 scrypt 해시만 저장합니다.
- 계정은 DB 최초 초기화 때만 원본에서 읽습니다. 이후 스냅샷 적용이나 CSV 등록으로 계정을 교체하지 않습니다.

3. 저장과 자동 재계산
- 영속 DB는 data/shuttle.sqlite입니다. SQLite WAL 관련 파일도 DB의 일부이므로 실행 중 임의로 옮기거나 삭제하지 마세요.
- 다른 DB 경로는 환경변수 SHUTTLE_DB로 지정할 수 있습니다.
- 최초 기준 데이터는 dataset_version=1, policy_version=1입니다. decision.json의 실제 D01 선택 B를 초기 정책에 반영합니다.
- 초기 정책: 최대 승차시간, 평균 승차시간, 실제 차량 대수, 운행 횟수, 총 운행시간 순의 사전식 최소화입니다.
- 정상 스냅샷 적용과 세 종류 테이블 편집은 dataset_version을 증가시켜 전체 기간 자동 계산합니다. 정책 저장은 policy_version을 증가시킵니다.
- UPDATING, CALCULATING 동안 현재 결과를 비우고 이전 지표는 STALE로 표시합니다. 완료한 현재 입력/정책 버전만 READY 또는 INFEASIBLE로 게시합니다.
- 오류 스냅샷은 422로 거부하고 기존 데이터, 버전, 노선을 보존합니다. 검증 결과와 거부 이력만 저장합니다.
- 동시 수정은 클라이언트가 읽은 데이터/정책 버전을 서버 현재 버전과 비교해 409로 거부합니다. 최신 변경이 계산 도중 도착하면 이전 작업을 취소하고 구버전 결과 게시를 차단합니다.
- 서버가 계산 도중 중단되면 다음 시작 시 현재 확정 입력으로 자동 복구 계산합니다. 완료한 결과와 정책, 세션, 변경 이력은 재시작 후 유지됩니다.

4. 화면 사용
- 운영자 화면의 스냅샷 선택에서 검증과 검증 후 적용을 실행합니다. 등록하려면 전체 10개 CSV와 constraints.json을 한 번에 선택합니다.
- 입력 테이블에서 shifts, stops, travel_times를 선택하고 행 검색 후 각 행의 저장 버튼으로 확정합니다. 수정 범위는 근무상태, 정류장 활성, 방향 이동시간입니다.
- 최적화 정책은 5개 지표의 순위를 중복 없이 지정하고 실제 선택 응답/이유를 입력해 저장합니다. 안전 제약은 완화할 수 없습니다.
- 전체 운행 결과에서 근무 시작일, 사업장, 근무조로 필터하고 운행 버튼을 눌러 현재 결과의 순서와 합성 좌표 노선도를 봅니다.
- JSON/CSV 내보내기는 현재 버전의 완료한 결과에만 허용됩니다. 구성원은 내보내기 API를 호출할 수 없습니다.
- 구성원은 날짜별 본인 사업장과 본인 탑승만 조회합니다. 야간조 퇴근은 실제 익일 시각으로 표시합니다.

5. 산출물과 제약
- artifacts/route_plan.json은 기준 데이터의 독립 계산 산출물입니다. 화면에서 시나리오를 적용하면 DB와 화면 내보내기는 그 최신 시나리오를 나타내며 기준 제출 산출물을 덮어쓰지 않습니다.
- artifacts/test-results.txt는 실제 테스트 실행 결과입니다. audit_result.json은 전체 입력 감사 결과입니다.
- IMPLEMENTATION_REPORT.md는 요구별 증거와 구현 한계, FINAL_REVIEW.md는 제출 전 최종 검토와 예상 Q&A입니다.
- HTTP 로컬 시험 환경용입니다. HTTPS와 외부 배포는 요구되지 않아 구현하지 않았습니다. 공개 인터넷 운영 환경으로 사용하면 안 됩니다.
- 브라우저는 사용자가 직접 검증합니다. Computer Use, Browser 자동화, 외부 서비스 호출을 사용하지 않았습니다.
