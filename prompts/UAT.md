# 사용자 참여형 기능 검증 (Guided UAT)

실제 과제의 README·R-ID·화면 요구와 현재 구현을 기준으로 사용자가 직접 검증할 전체 시나리오를 먼저 설계하고, 실행은 **한 번에 테스트 1건**씩 안내한다. Cofa Browser는 참가자가 직접 조작하며 Codex가 Browser를 자동 조작하거나 UAT PASS를 대신 선언하지 않는다. UI가 없는 과제에서는 해당 기능의 CLI/API/자동 검증으로 대체하고 사용자 Browser UAT를 억지로 생성하지 않는다. 실제 과제·공식 안내·시간 제한이 우선이다.

## 1. 전체 UAT 계획 먼저 작성 — 필수 R-ID 누락 방지

- 실제 과제에 명시된 **모든 필수 R-ID를 검증 커버리지 목록에 한 번 이상 연결**한다. 한 R-ID에 여러 사용자 행동이 있으면 기능별로 별도 UAT-ID를 만든다. 단순 서버 시작·페이지 렌더링만으로 주요 기능 전체를 커버했다고 보지 않는다.
- 사용자에게 보이는 필수 기능마다 직접 재현할 수 있는 UAT-ID를 준비한다. 가능한 범위에서 **역할별 로그인/권한 분리, 실제 조회·계산 결과, 날짜/조건 변경, 생성·수정·저장·재조회, 데이터 변경 후 실제 재계산, 오류 입력 거부 및 기존 결과 보존, 사용자별 접근 차단, 새로고침/재시작 지속성**을 확인한다. 실제 과제에 없는 기능은 만들거나 테스트한다고 주장하지 않는다.
- 화면만으로 확인할 수 없는 제약·알고리즘 불변조건·동시성은 별도 자동/API/독립 검산 케이스로 연결하고 해당 R-ID에 근거를 남긴다. **UI 시나리오가 없는 R-ID도 커버리지에서 삭제하지 않는다.** 불가능한 경우 이유와 NOT_RUN/BLOCKED, 남은 위험을 표시한다.
- 각 UAT-ID에 **R-ID, 테스트 목적, 테스트 계정/역할, 사전조건·데이터·실제 URL/포트, 참가자의 1~5단계 조작, 실행 전 기대 결과(화면·상태·수치), 실제 관찰 결과, 판정, 증거, 확인 시각·코드 판본, 재검증 필요 여부**를 둔다. 비밀번호·개인정보 원문을 불필요하게 복제하지 않는다.
- 기대값은 README/출력 계약/데이터·독립 검산에 근거하여 **실행 전에** 적는다. 기대 수치를 산출할 수 없다면 판별 가능한 동작·상태와 근거를 제시하고 미정 수치를 꾸미지 않는다. 실제 출력에 맞춰 기대값을 사후 수정하지 않는다.
- 사용자 UAT를 시작하기 **전에 전체 UAT 목록과 R-ID 매핑을 작성**하고, 모든 사용자 판정은 기본 NOT_RUN으로 초기화한다. 마지막에 생성하면 미시험 항목이 빠질 수 있다. 시간이 촉박하면 P0 필수 사용자 경로부터 실행하되 전체 목록과 미실행 이유는 보존한다.

## 2. 사용자에게 한 건씩 안내

서버·실제 포트가 준비되면 다음 형태로 **한 건만** 보여준다. Codex 사용자 응답은 평문 '1. 제목'과 '- 항목'으로 표현한다.

- UAT-ID / 연결된 R-ID / 확인할 기능
- 사전조건 (역할/계정, 데이터, 서버 주소·포트·경로)
- 사용자가 Browser에서 직접 실행할 단계 (1~5단계, 클릭·입력값·선택 날짜 등을 구체적으로)
- **실행 전 예상 결과** (직접 눈으로 볼 화면·수치·오류·유지되어야 할 상태)
- 응답 요청: 'PASS / FAIL / NOT_RUN / BLOCKED 중 무엇인가요? 실제로 보인 결과 또는 오류를 알려주세요.'

**사용자 응답 전 다음 사례로 넘어가지 않는다.** PASS는 사용자가 예상 결과와 일치함을 명시적으로 확인했을 때만 기록한다. 사용자 발언이 불명확하거나 기대 결과와 실제가 다르면 추가 확인/FAIL/NOT_RUN으로 보수적으로 기록한다. AI 자동 테스트 통과는 사용자 UAT PASS가 아니다. 업무 정책 결정은 별도 `cofa-decide` HITL이고 UAT PASS는 정책 승인과 다르다.

FAIL이면 실제 관찰·재현조건을 기록하고 원인 분석 → 승인 범위 내 수정 → 자동·회귀 검사 → **같은 UAT 재실행**을 안내한다. 테스트 후 영향받는 코드나 입력이 바뀌면 관련 PASS를 STALE로 바꾸고 재검증한다. 진행 불가 시 BLOCKED, 미실행은 NOT_RUN을 남긴다. 공식 시간상 중단해야 하면 다음 UAT로 넘어간 척하지 않는다.

## 3. FINAL_REVIEW.md에 최종 전체 목록 보존

- 실제 과제 기존 필수 검증 기록을 우선 활용하고, 추가 파일이 허용되면 실제 과제 폴더의 **FINAL_REVIEW.md 6. 테스트·UAT 결과**에 전체 UAT 목록을 **실행 전부터 작성·진행 중 갱신·제출 확정 전 최종 정리**한다. 중복 `VERIFY.md`를 새로 만들지 않는다. 추가 파일이 금지되면 허용된 기존 문서와 Codex 대화창에 같은 내용을 평문으로 남긴다.
- 6번 항목에는 (a) 자동/API/독립 검산 요약, (b) **전체 사용자 직접 확인 UAT 목록: UAT-ID·R-ID·목적·계정/사전조건·조작 절차·사전 기대 결과·실제 관찰·PASS/FAIL/NOT_RUN/BLOCKED/STALE·증거·판본**, (c) **R-ID별 커버리지 및 미실행/실패/재검증 필요 항목**, (d) 제출 전 가장 큰 미해결 위험과 다음 조치를 포함한다.
- 일부만 실행한 경우에도 **완료된 UAT만 골라 보여주지 말고 원래 계획한 전체 UAT를 유지**한다. 실제 사용자의 확인이 없으면 NOT_RUN이다. 최종 요약의 상태·개수는 세부 목록과 일치시킨다.
- 결과는 예시 데이터라고 명시하지 않는 한 꾸며 내지 않는다. 최종 파일은 평문 숫자 제목과 '- 항목'으로만 작성한다. 제출 확정 이후 AI를 사용하여 보완하지 않는다.
