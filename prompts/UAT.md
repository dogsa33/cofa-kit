# 사용자 참여형 기능 검증 (Guided UAT)

현재 서버/포트가 준비됐는지 확인한 후, 실제 과제 R-ID를 바탕으로 **한 번에 테스트 1건**을 진행한다. UI가 없으면 UAT 대신 자동/CLI 검증으로 대체한다.

Codex는 매번 아래만 안내한다:

- UAT-ID / 연결된 R-ID / 사전조건 (계정 역할, 테스트 데이터, 서버 포트·경로)
- 사용자가 Browser에서 직접 누를 것 (1~5 단계, 누가 어떤 값 입력하는지 구체적으로)
- **실행 전 기대 결과** (눈으로 확인할 화면·상태·수치. 실제 출력에 맞춰 기대값을 임의 변경하지 않음)
- 응답 요청: `PASS / FAIL / NOT_RUN / BLOCKED 중 무엇인가요? 실제로 보인 결과와 오류를 알려주세요.`

**사용자 응답 전 다음 사례로 넘어가지 않는다.** AI는 Browser를 자동 조작하지 않고, 사용자가 보고한 내용에만 사용자 확인 표시를 한다. 테스트 FAIL이면 이유를 조사하고 승인 범위 내 일반 버그를 최소 수정한 다음 동일 UAT를 재실행하도록 안내한다. **업무 정책 변경이 필요할 때만** 별도의 `cofa-decide` 질문으로 전환한다. UAT PASS는 정책 승인 및 전체 요구사항 검증 성공과 다르다.

기록은 과제의 기존 검증 파일을 재사용한다. 없으면 최소한 `VERIFY.md` 하나로 `ID/R-ID/입력/기대값/사용자 관찰/판정/확인 시각/코드 판본/재검증`을 기록한다. NOT_RUN/BLOCKED/STALE도 보존하고, 사용자의 실제 발언을 꾸며내지 않는다. 마지막 코드 변경 이후 영향받는 UAT는 다시 확인한다.
