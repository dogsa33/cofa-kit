# 최종 사용자 종합 검증 (Final UAT)

실제 과제의 README·R-ID·화면 요구와 최종 코드에 근거하여 **필수 기능 전체의 사용자 직접 검증 시나리오를 마지막에 한 번에 제시**한다. 개발 중에는 Codex가 자체 자동/API/독립 검산과 오류 수정·회귀 검증을 반복하되 **중간 UAT 질문·사용자 PASS/FAIL 요청으로 작업을 멈추지 않는다**. 핵심 정책 결정만 별도 HITL 대상이다.

## 1. 수행 시점 — 구현과 자체 검증이 끝난 뒤 한 차례

- 신규 과제의 분석·현업 질문·HITL 결정 후 필수 기능을 구현한다. 개발 중 검증은 Codex가 자율적으로 시행하는 코드·CLI/API·경계 사례·독립 검산이다. **구현 도중 사용자에게 UI를 하나씩 시험하라고 요구하지 않는다.**
- **최종 구현·자체 검증 후 제출 확정 전에** 한 차례 종합 UAT를 준비한다. 과제 특성상 UI가 없으면 사용자 Browser UAT를 강요하지 않고 CLI/API 검증 결과와 미검증 항목을 종합한다.
- 공식 시간이 부족하면 중요한 P0 사용자 경로를 우선 확인하고, 미실행 시나리오를 NOT_RUN으로 유지한다. 추가 UAT 때문에 필수 제출이나 공식 마감 시간을 놓치지 않는다. 실제 과제·운영 규정이 우선이다.

## 2. 사용자에게 전체 체크리스트를 한 번에 제시

- 실제 과제의 **모든 필수 R-ID에 대한 검증 커버리지**를 확인한다. 한 R-ID에 여러 역할·화면·동작이 있으면 적절히 분리한다. UI 검증 불가 항목은 삭제하지 않고 자동/API/독립 검산 근거와 한계를 표시한다.
- **전체 UAT 목록을 단일 보고로 제시**하며, UAT-ID마다 R-ID / 검증 목적 / 테스트 계정·역할·사전조건 / 실제 포트·URL·데이터 / **사용자 직접 조작 절차** / **실행 전 예상 결과** / 실제 관찰 결과 / 판정 / 증거·코드 판본을 명확히 적는다. 테스트 전 기대 결과는 과제 원문·데이터·독립 검산을 바탕으로 정의하고 사후 변경하지 않는다.
- 필수 경로에 맞춰 로그인·권한/소유권·역할별 화면, 실제 조회/계산, 날짜·조건 변경, 저장·재조회, 입력 변경 후 실제 재계산, 오류 입력과 기존 결과 보존, 새로고침/재시작을 포함한다. 과제에 없는 기능은 억지로 추가하지 않는다.
- 참가자는 Cofa Browser를 직접 조작하고 **전체 시나리오를 순서대로 자율 확인한 뒤, UAT-ID별 결과를 한 번에 묶어서 전달**할 수 있다. Codex는 시나리오마다 멈춰서 다음 단계 허락을 요구하거나 사용자에게 테스트 1건씩 질문하지 않는다.
- **검증 요청은 마지막 종합 점검 단계에 한 번만** 한다. 다만 사용자가 특정 FAIL 재현이나 추가 설명을 요청하면 해당 항목을 지원하고, 사용자에게 새로운 운영 정책 결정을 대신 요청하지 않는다. AI는 Browser를 자동 조작하지 않는다.

## 3. 실제 판정과 FAIL 처리

- 각 UAT는 사용자 보고가 없으면 NOT_RUN이다. PASS는 참가자가 기대 결과와 일치했다고 실제로 확인한 경우에만 사용한다. 실패는 FAIL, 환경 문제는 BLOCKED, 후속 코드 변경으로 이전 검증이 무효가 되면 STALE로 기록한다. AI의 자체 테스트 PASS를 사용자 UAT PASS라고 표시하지 않는다.
- 사용자가 **여러 UAT-ID의 결과를 한꺼번에 보고하면 일괄 반영**하고, FAIL은 원인·재현 조건을 확인하여 승인 범위 안에서 수정한다. 이후 Codex가 자동 회귀 검사를 수행하고, 영향받는 사용자 항목만 마지막 검증 과정에서 재확인하도록 정리한다. 검증 전체를 처음부터 반복하라고 요구하지 않는다.
- 실행하지 못한 항목을 지우거나 실제 관찰 내용을 꾸미지 않는다. 최신 코드 판본과 검증 시점이 다르면 영향을 받는 판정만 STALE로 갱신한다. UAT PASS는 HITL 정책 승인과 다르다.

## 4. FINAL_REVIEW.md 한 곳에 종합 보존

- 최종 UAT 체크리스트, 참가자 관찰, 실제 판정, **전 R-ID 검증 커버리지**, 자동/API/독립 검산 결과, 미시험·미해결 위험을 실제 과제 폴더의 `FINAL_REVIEW.md` **6. 테스트·UAT 결과**에 종합 작성한다. 최종 UAT를 시작하기 직전에 목록과 기대 결과를 작성해 제출 전 업데이트해도 된다. 개발 중 사용자 UAT 보고서나 별도 `VERIFY.md`를 만들지 않는다.
- 실제 과제에서 추가 파일을 금지한다면 허용된 제출 문서 또는 Codex 대화창에 동일한 평문 내용을 제공한다. 전체 항목은 PASS/FAIL/NOT_RUN/BLOCKED/STALE을 포함하고, 사용자 미확인 항목은 NOT_RUN으로 남긴다.
- 제출 확정 후에는 모든 AI 작업을 중단한다. 보고는 일반 숫자 제목과 '- 항목'의 평문만 사용한다.
