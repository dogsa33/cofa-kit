# 단일 Codex 진행 시나리오 — 제출 확정 전 단계 전용

다음 작업을 **하나의 Codex가** 진행한다. 별도 서브에이전트나 병렬 위임 없음. 실제 과제 README 및 운영 안내가 이 지침보다 우선한다.

1. **실제 과제 확인** — 과제 위치, README·AGENTS.md, 입력/출력 파일, 요구사항·예외·금지·제출 형식·기존 코드 탐색. `.cofa-kit/examples/`은 실제 과제 데이터가 아니다. `../skills/cofa-triage/SKILL.md` 적용.
2. **필수조건 추적** — 요구마다 R-ID, 출처, 구현 위치, 기대 결과, 실제 검증 상태를 **과제의 기존 기록 또는 최소 한 파일**에 정리. 필수 조건의 `dropped`, 미구현, NOT_RUN은 성공 아님. 승인되지 않은 예외 기준을 추정하지 않는다.
3. **HITL 게이트** — 결과를 바꾸는 미정 목표·업무 기준·민감정보·권한·자료 처리·큰 스택 변경만 `../skills/cofa-decide/SKILL.md`를 적용. **한 번에 한 결정**: 대안/추천/근거/장단점 제시 → 사용자 실제 답변 대기 → 선택·명시적 거절·미선택 구분 기록. AI 추천은 사용자 승인 아님. 응답 없음/"알아서"/UAT PASS는 승인 아님. 결정과 관계없는 다른 구현은 진행 가능.
4. **최소 구현** — `../skills/cofa-build/SKILL.md`. 기존 코드/파일/스택 우선. 승인된 범위의 함수 작성·버그 수정·테스트는 반복 승인을 요청하지 않는다. 입력→검증→처리→저장→출력의 작은 실제 흐름부터 확인.
5. **검증** — `../skills/cofa-verify/SKILL.md`. 필수 요구마다 정상·경계·오류 사례, 계산 불변조건, 보안·중복·동시성 등 실제 관련 위험을 확인. 실행한 명령/기대/실제/검증 시점을 기록. 수정 후 관련 재검증. 변경 전 PASS를 그대로 유지하지 않는다.
6. **사용자 UAT** — UI가 실제 있는 과제에만 `../prompts/UAT.md` 지침. 현재 서버 주소/포트 → 단계별 조작 → *사전* 기대 결과 → 응답 대기 → 사용자 PASS/FAIL/NOT_RUN/BLOCKED와 관찰 기록 → 실패 시 최소 수정/동일 사례 재확인. **테스트 결과는 정책 승인과 별도**.
7. **최종 설명** — `../skills/cofa-explain/SKILL.md`로 현재 파일·함수·API·데이터 흐름, 사용자가 내린 중요 결정과 명시적으로 거절한 안, 실제 검증과 미검증, 잠재적 한계, 작업 전/후 변경을 정리. 제출 버튼·브라우저 조작은 사용자가 한다.

추가 선택 지침:
- 반도체 계측·수율·조인/SPC 데이터가 실제 과제에 있으면 `../skills/cofa-semiconductor/SKILL.md`만 추가로 읽는다.
- 모델 학습·평가 과제라면 `../skills/cofa-model-eval/SKILL.md`만 추가로 읽는다.
- 통근버스 예제는 사전 연습 요청이 있을 때만 `../examples/shuttle/README.md`를 읽는다.
- **스킬 파일은 동작 규칙이지 독립 에이전트가 아니다.** 사용자가 매 단계 선택할 필요 없다.
- 외부 API, 개인 키, Git Push, 브라우저 자동화, 시험 내용 외부 전송은 하지 않는다. 후속 AI 사용 금지 단계에 들어가면 중단한다.

매 응답은 `실제로 한 일 / 확정된 기준과 결정 대기 / 검증됨·실패·미검증 / 다음 행동`을 짧게 제공한다. 모호한 기준만 사용자에게 묻고, 사소한 구현 질문을 늘리지 않는다.
