# 단일 Codex 진행 시나리오 — 제출 확정 전 단계 전용

다음 작업을 **하나의 Codex가** 진행한다. 별도 서브에이전트나 병렬 위임 없음. 실제 과제 README 및 운영 안내가 이 지침보다 우선한다.

## 신규 과제의 고정 순서 — 사전 분석 보고 전 기능 개발 금지

다음 1~4단계는 **순서대로 실제 조사·보고하는 필수 게이트**다. README를 읽거나 질문 목록만 출력했다는 이유로 데이터 감사가 완료됐다고 주장하지 않는다. 기존 과제를 이어서 수정할 때는 이미 검증된 결과를 재사용하되 영향받는 요구·데이터는 재확인한다.

1. **과제 및 요구사항 분석** — 실제 과제 작업 위치, README·AGENTS.md·기존 코드, 입출력, 제출 조건·금지사항을 확인하고 R-ID별 필수 요구를 정리한다. `.cofa-kit/examples/`은 실제 과제 데이터가 아니다. `../skills/cofa-triage/SKILL.md` 적용.
2. **전체 데이터셋 목록화·실제 데이터 감사** — 발견한 모든 입력 데이터셋과 변경 시나리오를 목록화해 용도, 파일별 행·열 수, 컬럼·형식·키, 관계를 설명한다. **실제 파일을 조사해** 결측·중복 키·참조 무결성·값 범위·날짜·시간대·논리 오류를 확인한다. 기준 데이터와 변경 데이터는 차이·영향을 구분한다. 명령/검사 범위(전체/표본/NOT_RUN)와 데이터 품질 문제·예상 영향·원본 보존 여부를 보고한다. 큰 데이터는 검사를 효율화하되 확인하지 않은 부분은 검증한 것처럼 쓰지 않는다.
3. **현업 확인 질문 목록 산출** — 위 감사와 과제 근거에서 **정말 미확정인 업무 사실**만 Q-ID·P0/P1/P2·대상·근거(README·파일·컬럼)·답변 영향·상태와 함께 한 번에 보고한다. README에 답이 있는 질문이나 사용자가 선택할 설계 판단은 현업 질문에서 제외한다. 없으면 `현업 확인 질문 없음` 및 **확인한 근거·감사 범위**를 제시한다. 질문 전달은 참가자가 현업 담당자에게 직접 한 건씩 수행한다.
4. **개발 계획·전략 보고** — R-ID 우선순위, 입출력·데이터 흐름, 구조·기술 스택, 계산/알고리즘 후보, 데이터 변경에 따른 재계산·오류 복구, 자동 검증·사용자 UAT, 제약·리스크·미확정 사항을 짧고 구체적으로 제시한다. **1~4단계의 실제 결과를 사용자에게 보고하기 전에는 본격적인 웹앱/알고리즘 구현을 시작하지 않는다.** 다만 읽기 전용 조사·임시 데이터 점검 스크립트는 허용한다. 기존 과제의 기록을 재사용하며 문서·폴더를 과도하게 늘리지 않는다.
5. **핵심 설계 HITL** — 현업 문의(업무 사실)와 참가자 결정(최적화 우선순위·정책 등)을 구분하고, 중요 결정은 `../skills/cofa-decide/SKILL.md`에 따라 **한 번에 한 결정**: 대안·근거·추천·위험 → 실제 답변 대기 → 선택·명시적 거절·미선택 기록. AI 추천·"알아서"·UAT PASS는 승인 아님. 미해결 P0 때문에 확정할 수 없는 부분은 보류하되 독립적인 승인 범위의 작업은 진행할 수 있다.
6. **최소 구현·반복 검증** — `../skills/cofa-build/SKILL.md`로 기존 코드·스택 우선 구현. `../skills/cofa-verify/SKILL.md`로 정상·경계·오류, 데이터 변경에 따른 실제 재계산, 보안·중복·동시성 등 과제 관련 위험을 실제 실행해 확인한다. 변경 전 PASS를 그대로 재사용하지 않는다. 개발 도중 새 중요 판단이 나오면 5단계 HITL을 다시 적용한다.
7. **사용자 수동 UAT** — UI 과제에서만 `../prompts/UAT.md` 지침으로 실제 포트/입력/조작/사전 기대결과를 한 건씩 안내 → 사용자 PASS/FAIL/NOT_RUN/BLOCKED와 관찰 기록 → 필요시 수정·재검증. UAT PASS는 업무 정책 승인과 별개.
8. **최종 설명** — `../skills/cofa-explain/SKILL.md`로 현재 코드·데이터 흐름, 사용자 결정·거절, 실제 검증·미검증, 취약점·한계를 정리한다. 제출 확정 후 AI 작업 중단.

추가 선택 지침:
- 반도체 계측·수율·조인/SPC 데이터가 실제 과제에 있으면 `../skills/cofa-semiconductor/SKILL.md`만 추가로 읽는다.
- 모델 학습·평가 과제라면 `../skills/cofa-model-eval/SKILL.md`만 추가로 읽는다.
- 통근버스 예제는 사전 연습 요청이 있을 때만 `../examples/shuttle/README.md`를 읽는다.
- **스킬 파일은 동작 규칙이지 독립 에이전트가 아니다.** 사용자가 매 단계 선택할 필요 없다.
- 외부 API, 개인 키, Git Push, 브라우저 자동화, 시험 내용 외부 전송은 하지 않는다. 후속 AI 사용 금지 단계에 들어가면 중단한다.

매 응답은 `실제로 한 일 / 확정된 기준과 결정 대기 / 검증됨·실패·미검증 / 다음 행동`을 짧게 제공한다. 모호한 기준만 사용자에게 묻고, 사소한 구현 질문을 늘리지 않는다.
