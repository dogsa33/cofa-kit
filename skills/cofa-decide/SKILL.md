# 중요한 결정은 사용자에게, 구현은 결정 이후에

이 스킬은 AI 사용이 허용된 **제출 확정 전** 단계에서만 적용한다. 과제 README와 주최 측 운영 규칙이 우선이다. 이 지침은 Cofa 화면이나 실무자 메신저를 자동으로 조작하지 않는다.

## 1. 결정의 주체를 먼저 구분

| 구분 | 처리 방식 |
| --- | --- |
| 과제에 이미 정해진 필수 조건·금지 조건 | 선택지로 재협상하지 않고 그대로 준수. 충돌 시 확인 질문 |
| 업무 규칙이 불명확한 것 | 시험에서 허용된 담당자에게 전달할 짧은 질문을 작성하고 **참가자가 직접** 전달 |
| 목표 함수·우선순위·상충 조건·핵심 아키텍처·데이터 정책·보안·권한 등 사용자 설계 판단 | **참가자에게 선택 요청**. 명시적 답변 전 해당 결정을 전제한 구현을 확정하지 않음 |
| 변수명·파일 분리·명확히 국소적인 구현 세부사항 | AI가 자율 결정. 별도 승인을 반복 요청하지 않음 |

기준: 선택에 따라 업무 결과, 검증 기준, 리스크, 사용자 경험 또는 큰 규모의 재작업이 바뀌는가? 그렇지 않으면 질문을 늘리지 않는다. 과제에 허용되지 않은 외부 도구나 보안 완화를 선택지로 제시하지 않는다.

## 2. 사용자 결정 게이트

중요한 미결정이 있으면 한 번에 **중요한 결정 한 개만** 우선순위대로 묻는다. 사용자 응답 전에 다음 정책 질문을 겹쳐 제시하지 않는다. 각 질문은 다음 형식으로 짧게 작성한다.

- **D-번호 / 무엇을 결정해야 하나:** 검토할 업무 목표와 과제 근거
- **대안 A/B(/C):** 얻는 효과, 치러야 할 비용 또는 잃는 것, 위험·경계 사례, 검증 방법. 수치는 실제 측정이 있을 때만 제시
- **AI 추천:** 추천안과 이유. 실제 사용자의 결정과 구분
- **사용자에게 묻는 문장:** `A/B/C 중 어떤 방향으로 진행할까요? 다른 기준을 지정해도 됩니다.`
- **대기 중 진행할 일:** 결정에 영향을 받지 않는 입력 검사·인터페이스 파악·테스트 준비

**선택되지 않은 대안을 자동으로 '거절'했다고 쓰지 않는다.** `NOT_SELECTED`와 명시적 `REJECTED`를 구분한다. AI 추천을 사용자 승인으로 오인하지 않는다.

## 3. 응답을 받은 뒤

1. 사용자가 실제로 응답했는지 확인하고 선택안과 발언 원문·근거를 기록한다. 사용자 발언에 없는 이유를 참가자 의견으로 만들어 적지 않는다. 설명이 불분명하면 질문을 좁히되 반복 질문으로 시간을 소모하지 않는다.
2. **선택(SELECTED)**, **명시적 거절(REJECTED)**, **단순 미선택(NOT_SELECTED)**, **보류(DEFERRED)**를 분리한다. 이미 확정한 결정을 변경할 땐 이전 결정을 보존한 뒤 새 결정·사유를 추가한다.
3. 승인된 범위에 따라 구현하고 관련 코드·함수·실제 데이터 흐름을 연결한다. 필요하면 `cofa-build`를 적용한다.
4. `cofa-verify`로 정상·오류·경계·동적 변경 시나리오를 실제 실행해 검증하고 검증 실행 명령, 결과, 시점, 남은 한계를 기록한다. 실행하지 않은 검사는 `NOT_RUN`, 브라우저 직접 확인이 필요한 것은 `HUMAN_CHECK`로 구분한다.
5. 제출 확정 전에 `cofa-explain`에서 **무엇을 선택·거절·수정했는지 → 왜 → 어떤 파일에 반영됐는지 → 검증 증거와 한계**를 짧게 정리한다.

## 4. 기록 매체와 선택형 로컬 CLI

실제 과제의 필수 문서·기존 결정 기록을 최우선으로 사용한다. 기록이 있으면 중복 문서를 새로 만들지 말고 해당 기록에 추가한다. 없고 과제 규칙이 허용하는 경우에만 작업 공간 안에서 결정 로그를 남긴다. 준비 키트에는 **선택형** 로컬 표준 라이브러리 도구 `scripts/decision_log.py`가 있다. CLI 사용 여부가 중요 결정을 묻고 기록할 의무를 대체하지 않는다.

```bash
# Codex의 실제 작업 폴더에서 실행하는 예시. 가상 선택지이며 시험 정답이 아님
python3 .cofa-kit/scripts/decision_log.py --workspace . propose --id D-001 --topic "최적화 목표" --option "A::비용 우선" --option "B::시간 우선" --recommend B --basis "업무 우선순위 미정"
# 다음 select 명령은 반드시 참가자가 선택을 실제 응답한 뒤에만 실행. 별도 거절 발언이 없다면 --reject 금지
python3 .cofa-kit/scripts/decision_log.py --workspace . select --id D-001 --choice B --user-reply "B를 선택합니다"
python3 .cofa-kit/scripts/decision_log.py --workspace . implement --id D-001 --file src/optimizer.py --note "선택한 목표를 계산식에 반영"
python3 .cofa-kit/scripts/decision_log.py --workspace . verify --id D-001 --status NOT_RUN --note "아직 검증하지 않음"
python3 .cofa-kit/scripts/decision_log.py --workspace . report
```

CLI는 참가자의 동의 여부나 테스트 성공을 **독립적으로 증명하지 않는다**. 반드시 현재 대화·실제 사용자 확인·실행 결과를 대조한다. 로그는 기본적으로 실제 작업 폴더의 `.cofa-decisions.jsonl`에 추가 기록한다. 원본 문제·개인정보·비밀키를 로그에 포함하지 말고 외부로 전송하거나 Git Push하지 않는다. 여러 작업자가 동시에 같은 로그를 쓰지 않는다.

## 5. 시간이 부족하거나 답변이 없는 경우

큰 설계 결정이 미확정이면 그 선택에 의존하는 구현을 **완료로 주장하지 않는다**. 결정과 무관한 부분은 계속 진행한다. 일정상 확정 없이 가야 한다면 사용자가 승인한 범위 내에서만 되돌리기 쉬운 임시 선택을 하고 **임시 가정 및 미확인**으로 표시한다. 보안, 개인정보, 필수 제약 위반을 임시 선택으로 정당화하지 않는다.

## 6. 제출 경계

제출 확정 후에는 의사결정 요약 갱신, 대화, Skill, AI 분석을 멈춘다. 후속 서술형 질문은 참가자가 AI·복사/붙여넣기 없이 직접 답한다. 시험 내용·코드·로그를 외부에 전송하지 않는다.
