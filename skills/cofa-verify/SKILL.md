# 실제로 확인한 것만 PASS

1. 필수 R-ID별로 소스·함수·입력/출력·기대 결과·검사 명령/사용자 확인 여부·**현재 코드 판본**을 대조한다. `dropped`, `skip`, `NOT_RUN`, `BLOCKED`, `STALE`은 필수조건 성공이 아니다.
2. 정상·실패·경계 케이스를 실제 실행한다. 결과를 근거로 예상값을 뒤바꾸지 않는다. 검사 0건, 서버 시작, 파일 존재만으로 전체 성공을 주장하지 않는다.
3. 알고리즘·분석 결과는 가능한 한 **독립적인 작은 입력/손 계산/불변조건 검사**로 재검산한다. 특히 관계키 중복·행 증폭, 중복 배정·누락, 용량, 시간 경계 등을 확인한다.
4. 실제 과제에 관련된 입력 누락·중복·0건·음수/NaN, 야간조·휴일, 변경 후 재계산, 역할별 서버 권한, 데이터 지속성·동시 수정, 복구·한계를 영향도 순으로 검증한다. 위험이 없으면 억지로 새 프레임워크/테스트 인프라를 만들지 않는다.
5. **개발 중에는 Codex 자체 자동/API/독립 검산과 오류 수정·회귀 테스트만 반복**하고 참가자 Browser UAT를 요청하거나 PASS/FAIL 응답을 기다리지 않는다. **전체 필수 기능 구현·자체 검증이 끝난 마지막 단계에서만** `../../prompts/UAT.md`에 따라 모든 필수 R-ID의 사용자 직접 검증 시나리오(UAT-ID·역할·조작·사전 기대 결과)를 **한 번에 종합 제시**한다. 참가자가 여러 건의 관찰을 묶어서 보고하도록 하며, 시나리오별 진행 허락을 요구하지 않는다. 화면에서 직접 검증할 수 없는 R-ID는 자동/API/독립 검산으로 구분한다. 사용자 PASS/FAIL은 **핵심 정책 결정의 승인 신호가 아니다**.
6. 개발 중 자체 테스트 FAIL은 사용자에게 확인을 요구하지 않고 원인 조사→승인 범위 내 최소 수정→동일 실패 테스트+관련 정상 테스트로 검증한다. **마지막 종합 UAT에서** 사용자 보고 FAIL이 나오면 해당 기능만 수정·자체 회귀 검사 후 영향받는 UAT에 한해 재확인한다. 정책 변경이 필요할 때만 새로운 HITL. 변경으로 무효화된 검증은 STALE로 둔다.
7. 제출 전 필수 산출물의 실제 경로·형식·파일명 확인, PASS/FAIL/NOT_RUN/BLOCKED/STALE 개수 및 미해결 문제·실제 위험을 정리한다. **FINAL_REVIEW.md 6번에 전 R-ID 커버리지 및 미실행 항목을 포함한 전체 UAT 절차·사전 기대 결과·실제 결과·판정이 남았는지 검토**한다. 코드 변경 뒤 관련 UAT는 STALE로 관리한다. 테스트 통과를 만들어내지 않는다.

**도구:** `scripts/data_tools.py`, `scripts/source_guard.py`, `examples/shuttle/verify_routes.py`는 선택형 로컬 도구이며 실제 과제 유형과 맞을 때만 사용. 통근버스 예제는 공식 채점기나 최적화 엔진이 아니다.
